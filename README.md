# System Design from Scratch

A personal desktop app (Electron + React + TypeScript) for learning system design from scratch. It
teaches each topic with a generated lesson, checks it with a quiz, loops on remediation lessons until
the topic is mastered, then moves on to design exercises on a diagram canvas. Content is generated by
driving the Claude Code CLI and grounded on the System Design Primer, in French (the default) or
English, chosen at the first launch and changeable in Settings. It has a light theme ("Warm") and a
dark one ("Terminal Architect"), chosen in Settings (the default follows your system). See [docs/Home.md](docs/Home.md) for the product spec, roadmap and
glossary.

**Website: <https://jbclaramonte.github.io/system-design-from-scratch/>** (a tour of the app with
screenshots, and the download; its source is in [`site/`](site/), see [docs/Website.md](docs/Website.md)).

## Download

Packaged apps are attached to each [GitHub Release](https://github.com/jbclaramonte/system-design-from-scratch/releases/latest). Personal use: not notarized (macOS signature is ad hoc, no Developer ID). Each release also has a `SHA256SUMS` file.

**macOS (Apple Silicon)**, one command, no Gatekeeper dialog:

```bash
curl -fsSL https://raw.githubusercontent.com/jbclaramonte/system-design-from-scratch/main/install.sh | bash
```

It downloads the latest `.dmg` with `curl`, checks its checksum, and copies the app to
`/Applications` (run it again to update; `VERSION=v0.1.1` picks a release, `INSTALL_DIR=$HOME/Applications`
another folder). `curl` leaves no quarantine attribute on the file, which is why macOS opens the app
without asking. Read [install.sh](install.sh) before piping it to a shell.

**Linux (x64)**, the same command (it detects the platform), no `sudo`:

```bash
curl -fsSL https://raw.githubusercontent.com/jbclaramonte/system-design-from-scratch/main/install.sh | bash
```

It downloads the latest AppImage, checks its checksum, installs it in
`~/.local/share/system-design-from-scratch/` and adds a launcher, so **System Design from Scratch**
appears in the application menu (run it again to update; `VERSION` and `INSTALL_DIR` work as on
macOS). It refuses to replace a running instance, never touches your data folder
(`~/.config/system-design-from-scratch/`) and, when FUSE 2 is missing, prints the fix and writes a
launcher that extracts the app on each start. By hand instead of the script: download the AppImage
from the release page, `chmod +x system-design-from-scratch-<version>-x86_64.AppImage`, and run it
(it needs FUSE 2: `sudo apt install libfuse2` on Ubuntu 22.04, `libfuse2t64` on 24.04; or start it
with `APPIMAGE_EXTRACT_AND_RUN=1`). The AppImage does not add a menu entry by itself, which is what
the script does.

> **Ubuntu 22.04 (x64, GNOME) is the oldest supported release.** The Electron binary needs glibc 2.25
> or later (Ubuntu 22.04 has 2.35) and the package is checked in CI on an Ubuntu 22.04 runner. Ubuntu
> 24.04 restricts unprivileged user namespaces, which an AppImage needs for Chromium's sandbox: use
> the `.deb` there (see [Linux](#linux-x64)).

## Prerequisites

- Node.js 24 LTS (22.18 or later works, the tests need the built-in `node:sqlite`; CI runs on 24)
  and npm.
- The [Claude Code CLI](https://docs.claude.com/en/docs/claude-code) installed and logged in. The app
  drives it as a subprocess for every generation, so it is required at runtime (not for building or
  testing). See [Claude Code CLI](#claude-code-cli) below.

## Getting started

```bash
npm ci
npm run dev
```

Electron no longer downloads its binary at install time. `npm run dev` and `npm run preview` run
`install-electron` first, which downloads it once and is a no-op afterwards.

### IPC

`src/shared/ipc.ts` is the single contract between the renderer and the main process. It declares
each channel with its request and response types and maps it to a `window.api` method. The preload
builds `window.api` from that map, and the main process must provide a handler for every channel
(enforced by the type of `registerHandlers`). The renderer never touches `ipcRenderer` directly.
Events pushed by the main process (such as `generation:event`) are declared in `IpcEvents`, exposed
as `window.api.on...` subscriptions that return an unsubscribe function, and sent with `sendEvent`
(`src/main/ipc/sendEvent.ts`).

### Database

The main process keeps everything in a local SQLite file, `system-design-from-scratch.db` in the
Electron `userData` directory, opened at startup with WAL and foreign keys on. It uses the built-in
`node:sqlite` module (no native dependency to rebuild) behind the small `Database` interface in
`src/main/db/driver.ts`. Migrations live in `src/main/db/migrations/`: append a new numbered one,
never edit an applied one; each runs in a transaction and is recorded in `schema_migrations`. The
schema is documented in [docs/Data Model.md](docs/Data%20Model.md).

### Claude Code CLI

Every generation (lessons, remediation lessons, quizzes, free-answer grading, design feedback) is
one call to the `claude` CLI, made by the Generation service in `src/main/generation/`. Calls draw
on your Claude subscription. Requirements:

- `claude` installed and logged in (run `claude` once in a terminal). If it is missing or logged
  out, generations fail with an explicit `cli_not_found` or `not_logged_in` error.
- An app launched from Finder or the Dock (macOS), or from a Linux application menu or `.desktop`
  launcher, does not see your shell PATH. The app looks for `claude` on PATH, then in
  `~/.claude/local`, `~/.local/bin` (where the native installer puts it on Linux and macOS),
  `/opt/homebrew/bin`, `/home/linuxbrew/.linuxbrew/bin`, `/usr/local/bin`, `~/.npm-global/bin`, then
  asks your login shell (`$SHELL`, else zsh on macOS and bash on Linux). To force a path, set it in **Settings > Claude
  Code CLI path** (applied at once; the **Test** button runs `claude --version` and
  `claude auth status` on it). The
  `CLAUDE_CLI_PATH=/absolute/path/to/claude` environment variable is still read when the setting
  is empty (development, tests).
- **Troubleshooting "Claude Code is not logged in" (`not_logged_in`)**: the app uses the CLI
  profile of the environment it was started from, `~/.claude` unless `CLAUDE_CONFIG_DIR` is set.
  If you log in with another profile (for example `CLAUDE_CONFIG_DIR=~/.claude-perso`), an app
  started from Finder, the Dock or a shell without that variable uses `~/.claude`, whose session
  may be expired ("Failed to authenticate: OAuth session expired"). Open **Settings > Claude
  config directory**, set the absolute path of the logged-in profile, press **Test** (it runs
  `claude auth status`: login state, auth method, account, config directory) and save; it
  applies at once. Or log that profile in again: `CLAUDE_CONFIG_DIR=<dir> claude`, then `/login`.
  Every generation error of this kind shows an **Open Settings** button.
- Each call runs isolated from your Claude Code setup (no hooks, plugins, MCP servers, settings or
  tools), with `--model sonnet --effort low`, from an empty temp directory.

The tests never call the real CLI: they use a fake `claude` script. One opt-in test makes 2 real
calls: `RUN_CLI_INTEGRATION=1 npx vitest run src/main/generation/cli.integration.test.ts`. To check
the content prompts on real output, `node scripts/prompt-quality-check.ts [topic-id]` makes at most 5
real calls and writes a sample under `docs/samples/` (see [docs/Prompts.md](docs/Prompts.md); a
Foundations Module slug such as `how-the-web-works` runs the ungrounded prompts). Details,
flags and error codes: [docs/Generation Service.md](docs/Generation%20Service.md); measurements
behind the choices: [docs/spikes/cli-latency.md](docs/spikes/cli-latency.md).

### Markdown and diagrams

Every Markdown view (lessons, Remediation Lessons, Protocol Step Lessons) renders through
`MarkdownContent` (`src/renderer/src/markdown/`): GFM, no raw HTML, http(s) links only.
` ```mermaid ` blocks are drawn as diagrams by `MermaidDiagram`, with `mermaid` loaded on first use
(not in the main bundle), `securityLevel: 'strict'`, size and node limits, and a fallback to the
source as code when a diagram cannot be drawn. **Diagrams (dev)** under Developer tools shows the
fixtures. See [docs/Mermaid Diagrams.md](docs/Mermaid%20Diagrams.md).

### Security

The window runs with `contextIsolation`, `sandbox` and no `nodeIntegration`. The renderer has a
restrictive Content Security Policy, navigation away from the app is blocked, links that open a new
window go to the OS browser (http and https only), and permission requests are denied. The renderer
makes no request (`connect-src 'self'`); the only network access of the app itself is the update
check, made by the main process.

## Packaging

To build it yourself, `npm run package` builds an installable macOS app (Apple Silicon only, personal use: not signed, not
notarized). Prerequisites: macOS on arm64, `npm ci`, and Electron installed
(`npx install-electron`, done by `npm run dev`). It runs `electron-vite build`, then electron-builder
(`electron-builder.yml`, packaging the Electron already in `node_modules`, so no Electron
download), then `scripts/check-package.mjs`, which fails if the Chromium licenses
(`LICENSES.chromium.html`) or Electron's license are missing, or if `.env*`, `src/`, `docs/` and
similar ended up in the app. The first `.dmg` build downloads electron-builder's dmg tooling once.

- Output (git-ignored): `dist/mac-arm64/System Design from Scratch.app` (about 360 MB) and
  `dist/system-design-from-scratch-<version>-arm64.dmg` (about 130 MB). `npm run package:dir` skips
  the `.dmg`.
- Install: open the `.dmg` and drag the app onto Applications, or copy the `.app` to
  `/Applications`. A build made on this machine opens normally. A copy downloaded in a browser or
  sent to another Mac is quarantined: see [Download](#download) (install script, **Open Anyway**,
  or `/usr/bin/xattr -dr ...`). The app is signed ad hoc (`identity: "-"`) and the guard script
  verifies the signature.
- Data: the packaged app uses the same folder as `npm run dev`,
  `~/Library/Application Support/system-design-from-scratch/` (database, caches), so existing data
  is reused. The Claude Code CLI is still required (see [Claude Code CLI](#claude-code-cli)).
- The icon (`build/icon.icns`) comes from `npm run icon:build`.
- Smoke test: `npm run smoke:packaged` launches the packaged app with a minimal environment
  (`PATH=/usr/bin:/bin`, a scratch HOME with a fake `claude` in `~/.local/bin`, a scratch
  `--user-data-dir`), drives it over the DevTools protocol and checks the Learning Path, Settings,
  About, a lesson with a Mermaid diagram and an exercise canvas. It never touches your real data.
  It does not cover the real CLI, the network, Gatekeeper on a downloaded copy or a Finder launch:
  follow the first launch checklist for those.
- Details, what the package contains, the license requirements, the smoke test
  and the first launch checklist: [docs/Packaging.md](docs/Packaging.md).

### Linux (x64)

The Linux app is built by GitHub Actions on an Ubuntu runner, not from macOS: the workflow
`.github/workflows/package.yml` (**Actions > Package > Run workflow**, or a `v*` tag) runs
`npm run package:linux` (AppImage and `.deb`, unsigned; the AppImage updates itself, the `.deb` only announces updates), the guard
script (`scripts/check-package.mjs --platform linux`), the smoke test under `xvfb-run`, the glibc
check, the test of `install.sh`, and uploads the two files as the artifact `linux-x64` (kept 14
days). A second job starts the AppImage on Ubuntu 22.04.

- AppImage: the install command in [Download](#download), or `chmod +x system-design-from-scratch-<version>-x86_64.AppImage` and run it. It needs
  FUSE 2 (`sudo apt install libfuse2t64` on Ubuntu 24.04, `libfuse2` before) or start it with
  `APPIMAGE_EXTRACT_AND_RUN=1 ./<file>.AppImage` (no FUSE needed). On Ubuntu 24.04 and other systems that restrict unprivileged user
  namespaces an AppImage may refuse to start (Chromium sandbox); see
  [docs/Packaging.md](docs/Packaging.md#linux-x64).
- deb (Debian, Ubuntu): `sudo apt install ./system-design-from-scratch-<version>-amd64.deb`. It sets
  up the sandbox helper and the AppArmor profile; the app appears in the Education category.
- Data: `~/.config/system-design-from-scratch/`. The Claude Code CLI is still required.
- Not verified: no real display and no real Claude Code CLI in CI, and no run on a real desktop
  (Wayland, window manager, launcher icon). See [docs/Packaging.md](docs/Packaging.md#linux-x64).

The same workflow builds the macOS dmg on a macOS runner and, on a `v*` tag, attaches both packages
to a draft GitHub Release ([Download](#download)).
