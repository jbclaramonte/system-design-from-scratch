# Recall Quiz and Memory Review Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Before each new Lesson, a short Recall Quiz on earlier Topics (more questions on notions often missed), plus a Memory Review screen of the notions that do not stick.

**Architecture:** Pure functions (answer history per notion, eligible Topics, question selection) in a new `src/main/recall/`. A Recall session is its own table, not a Round; its Attempts have `round_id` NULL and a new `recall_session_id`, so every Round-based computation (mastery, Dashboard, XP, Streak) ignores them. New questions are a quiz row per Topic marked `purpose = 'recall'`, generated by the existing quiz pipeline (`prepareQuiz`/`saveQuiz` with `focusNotions`, `count`, `avoidPrompts`, `types`), so no new prompt and no new Content Cache kind.

**Tech Stack:** TypeScript, `node:sqlite` through `src/main/db/driver.ts`, vitest (node environment, pure `.ts` tests, no React component tests), Electron IPC with zod, React.

**Spec:** `docs/superpowers/specs/2026-10-25-recall-quiz-design.md` (approved). Read it first; this plan only records decisions the spec leaves to the builder.

**Issues:** Task 1 is #70, Task 2 #71, Task 3 #72, Task 4 #73, Task 5 #74, Task 6 #75, Task 7 #76 (label `mastery-loop`); commits reference them (`Refs #70`, the last commit of an issue says `Closes #70`).

## Global Constraints

- English everywhere in the repo (code, comments, UI strings, docs, commits). Use glossary terms exactly: Recall Quiz, Memory Review, Shaky Notion, Round, Attempt, Notion, Topic, Lesson, Pre-generation, Declared Mastery. Never "review", "flashcards", "weakness", "gap" (see `docs/Ubiquitous Language.md`).
- Recall Attempts never change mastery, Weak Points, XP, Levels, Badges, the Activity Streak or the Daily Goal.
- The Mastery Loop, unlock rules, Forced Unlock and Declared Mastery are unchanged. A Recall Quiz is always taken, never blocks the next Lesson, and a technical failure never traps the learner (the Lesson opens).
- Recall question types: single choice, multiple choice, scenario only, all graded locally. No Generation to grade, no contest of a grade. Old free-answer questions are not reused.
- At most one batch Generation per finished Lesson, plus at most one declared Topic without a Notion Outline; both are Pre-generations (`GenerationService.pregenerate`), never awaited by the learner, never an error shown to the learner.
- Window = last 6 answers per notion, one result per Question per session (the final one), completed sessions only (Rounds and Recall sessions), `correct` only when `result === 'correct'`; `partially_correct` and `incorrect` count as missed. Declared Mastery and Forced Unlock never produce an answer.
- Notion status, in this order: fewer than 2 answers = untracked; missed >= 3 of the last 6 = `needs_attention`; correct on the last 4 (or all, if fewer than 4) = `solid`; every other tracked notion = `steadier`.
- Eligible Topics: passed (a Round with `passed = 1`, or a Declared Mastery), minus the most recently passed Topic and minus the Topic being opened. A Topic's passed date is the earliest of its first passing Round `completed_at` and its `declared_masteries.created_at`.
- Reused questions must be in the current Generation Language (`quizzes.language`), not flagged, not replaced.
- Migrations are additive (an older app refuses a newer database, see #69). The next migration is version 11.
- Tests never call the real Claude CLI (inject a fake `CliRunner`, see `src/main/mastery/service.test.ts`), never touch the real data folder, use `openDatabase(':memory:')` + `migrate(db, migrations)`.
- Work on the local branch `feat/recall-quiz` in the main working tree (no worktree: `node_modules` lives here and `npm install` is not available to agents). Local commits on that branch are authorized by the owner; never push, merge, tag or release. Each task below is one GitHub issue (already created and in `docs/ROADMAP.md`); keep the ROADMAP status tags current (`active`, `done`).
- Gate before every task is done: `npm run lint`, `npm run format:check`, `npm run typecheck`, `npm test`.

## Review Focus

- Language switch: Generation Language changed from French to English after Rounds were played; Recall must not serve French questions to an English learner (Task 2 test).
- A Topic both declared and later passed by a Round: counts once, passed date is the earliest of the two (Task 1 test).
- App closed mid-Recall Quiz: reopening the Lesson resumes the same session with its answers; once finished it is never asked again for that Topic (Task 4 test).
- Only one eligible Topic, or eligible Topics with no usable question and no stored batch: no Recall Quiz and no error (Task 1 and Task 4 tests).
- A topic with a recall quiz row must still show a single Round quiz in the quiz list and the Mastery Loop (Task 2 test); Recall Attempts must not appear in the Dashboard, rewards or path (Task 2 test).
- A batch whose generated prompts repeat questions already asked: `avoidPrompts` must carry every previously asked prompt on those notions (Task 3 test).
