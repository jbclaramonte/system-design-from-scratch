# Packaging

How the macOS app (Apple Silicon, arm64) is built from the repo with [electron-builder](https://www.electron.build/). Personal use, built locally: no signing identity, no notarization, no auto-update, no CI release. Context: [[Attribution and Licenses]] (what must travel with the app), [[SPEC]].

> [!note] Upcoming
> The tldraw license key handling in a packaged build and an automated smoke test of the package are separate tasks (#38 and #39). Until the key is handled, the Design Canvas of a packaged build stops rendering after 5 seconds without a valid key ([[Design Canvas Integration#License key]]).

## Build

Prerequisites: macOS on Apple Silicon, Node.js 22.18 or later, `npm ci` done, and the Electron binary installed (`npx install-electron`, run by `npm run dev` and `npm run preview`). No network is needed once Electron and the dmg tooling are in place.

```bash
npm run package       # electron-vite build, electron-builder (.app + .dmg), then the guard script
npm run package:dir   # same without the .dmg (faster, for checking the .app)
```

Output in `dist/` (git-ignored):

| Path | What |
|---|---|
| `dist/mac-arm64/System Design from Scratch.app` | The app, about 360 MB (Electron itself is most of it). |
| `dist/System Design from Scratch-<version>-arm64.dmg` | Disk image with the app and an Applications shortcut, about 130 MB. |

The config is `electron-builder.yml`. Notes on the choices:

- `electronDist: node_modules/electron/dist`: the Electron already installed is packaged, nothing is downloaded for it. electron-builder still downloads its dmg tooling (`dmgbuild-bundle`) once, on the first `.dmg` build, into its cache; later builds are offline.
- `identity: null`: the app is not code-signed by electron-builder. The Electron binary from npm carries an ad-hoc linker signature and starts on Apple Silicon as is (checked).
- `npmRebuild: false`: the app has no native module (`node:sqlite` is built into Electron's Node).
- `publish: null`: no update feed (`latest-mac.yml`) is generated.
- The icon `build/icon.icns` is generated by `npm run icon:build` (`scripts/build-icon.mjs`, run with Electron, needs macOS `iconutil`): the brand mark of the app header on a dark rounded square. Rerun it and commit the result only when the design changes.

## What is in the package

`app.asar` holds `package.json`, `out/` (the electron-vite output: main, preload and the renderer with its inlined fonts and tldraw assets) and `resources/` (`corpus/primer.json`, `licenses.json`, `licenses/`). Nothing else: no `src/`, `docs/`, `spikes/`, `screenshots/`, `scripts/`, tests, `.env*`.

The app ships no `node_modules`. The renderer is bundled by Vite, and the main process bundle includes its only runtime package, `zod` (`electron.vite.config.ts`, `externalizeDeps.exclude`). A package added later to the main or preload side must be bundled too, or the guard script fails.

Outside the asar, in `Contents/Resources/`:

- `LICENSES.chromium.html`: the Chromium, Node.js and other notices that Electron distributes. Electron ships it next to `Electron.app`, not inside it, and electron-builder does not copy it into a macOS app, so `extraResources` does.
- `LICENSE.electron`: Electron's own MIT license.

### Guard script

`scripts/check-package.mjs` runs at the end of `npm run package` and exits 1 when:

- `LICENSES.chromium.html` or the Electron license is missing from the `.app`;
- `app.asar` lacks a runtime file (`out/main/index.js`, `out/preload/index.js`, `out/renderer/index.html`, `resources/corpus/primer.json`, `resources/licenses.json`) or contains an environment file (`.env`, `.env.local`...), a top-level `src`, `docs`, `spikes`, `screenshots`, `scripts`, `build`, `.github`, `.vitest` or `node_modules`, or a test file;
- the main or preload bundle requires a package other than Electron and Node built-ins;
- there is no `.dmg` (not checked with `--app-only`, used by `package:dir`).

A key baked into the renderer bundle (`VITE_TLDRAW_LICENSE_KEY` from `.env.local`) is not an `.env` file in the package and is not checked here: that is the tldraw key task.

## User data

The packaged app uses the same folder as `npm run dev` and `npm run preview`: `~/Library/Application Support/system-design-from-scratch/` (the SQLite database `system-design-from-scratch.db`, caches). The folder is named after the package name, not the product name ("System Design from Scratch"), so `src/main/index.ts` sets `userData` explicitly at startup unless a `--user-data-dir` switch is given (tests and verification runs use a scratch folder that way). Existing data is reused as is; a packaged app enforces the Learning Path locks that dev builds skip (`app.isPackaged`).

The app still needs the Claude Code CLI at runtime (see the README). An app opened from Finder does not see the shell PATH: set the CLI path in **Settings** if `claude` is not found.

## Open an unsigned build

A package built locally has no quarantine attribute, so macOS opens it without a Gatekeeper prompt: drag the `.app` to `/Applications` (or open the `.dmg` and drag it onto the Applications shortcut), then open it.

A copy that was downloaded, AirDropped or sent by message gets the quarantine attribute and macOS refuses it as unverified. Either right-click the app, choose **Open**, then **Open** again; or remove the attribute:

```bash
xattr -dr com.apple.quarantine "/Applications/System Design from Scratch.app"
```

## Chromium license requirement

Chromium and the other bundled components require their license notices to be kept in every distribution. Electron provides them as `LICENSES.chromium.html`. Never strip it from a package; the guard script enforces it. The About screen lists the npm packages ([[Attribution and Licenses]]); this file covers Chromium and Node.js.

## Rebuild after a change

1. `npm run licenses:check` (after a `package-lock.json` change, `npm run licenses:build` first).
2. `npm run package`.
3. Replace the app in `/Applications` (quit it first). The data folder is untouched.

To try a build without touching your data, launch the binary with a scratch folder: `"dist/mac-arm64/System Design from Scratch.app/Contents/MacOS/System Design from Scratch" --user-data-dir=/some/scratch/dir`.
